给插件接上“检查更新 / 安装更新”（一页纸）

要求 Node 22+，零运行依赖。你只写 6 行 + 1 条命令，剩下的（轮询、门控、中文提示、重启横幅、排队、跳过、诊断复制）全在组件里。

第 1 步：装包

npm install dsh-plugin-update

第 2 步：宿主接线（4 行）

import { createHostUpdate } from 'dsh-plugin-update'

const update = createHostUpdate({ ctx, logCtx }, {
  pluginId: 'my-notes-plugin',   // 换成你的插件名
  prefix: 'notes',                // 换成你的前缀，多插件靠它隔离
  targetPackageName: 'my-notes-plugin',
})
for (const [name, handler] of Object.entries(update.handlers))
  registry.set(name, handler)    // 得到 notes.updateStatus / Check / Install

升级本包以后这里不用改代码，只升版本号。

第 3 步：面板挂载（2 行 + 1 条命令）

先生成电话名（prefix 改了就重跑一次）：

node node_modules/dsh-plugin-update/derive-client-values.mjs --prefix notes --out scripts/generated/updateClient.derived.js

再放一个挂载点：

import { mountUpdatePanel } from 'dsh-plugin-update/panel'

const panel = mountUpdatePanel(document.getElementById('update-slot'), {
  pluginId: 'my-notes-plugin',
  prefix: 'notes',   // 必须和宿主侧一致
  call: (name, args) => host.call(name, args),
})
// 离开时 panel.unmount()：只停轮询，安装在宿主侧继续跑；重开 1 秒内恢复显示

到手的效果

  • 有新版 → 横幅提示 → 点安装 → 关面板也不停
  • 装不上 → 中文一句话 + 可复制的手工命令；旁边“复制诊断”一键给出脱敏文本
  • 排队默认只看自己的；“已跳过 X.Y.Z · 恢复”在同一行，不藏设置
  • 更新说明读包内 CHANGELOG.md（Added/Fixed/Changed），没有就中性提示，不挡安装
只要一种接法：整组件就是默认。直接调三个电话属于无界面/自绘面板的高级用法，契约冻结可用，但新插件不用学。换肤加 theme: 'd5-paper' 即 D5 档案卷，不传即最小默认。

只要一颗按钮（入口件）

import { mountUpdateEntry } from 'dsh-plugin-update/entry'
mountUpdateEntry(document.getElementById('upd-entry'), {
  pluginId: 'my-notes-plugin', prefix: 'notes', call: (n, a) => host.call(n, a),
})
// 按钮文案自己变：检查更新 / 有新版 1.1.0 / 正在安装… / 待重启 / 更新失败，点此查看
  • 默认进页面静默查一次（只读，不联网签凭证），有新版才弹面板；没新版只在原地给一句「已是最新 X.Y.Z」
  • 三种形态：variant:'button'（默认）/ 'badge'（只给状态点）/ 'inline'（面板直接嵌进来）
  • 已有自己的更新页：openOn:'manual' + onActivate({hasUpdate, latestVersion})，跳转你自己做
  • 铁律：入口件只做「查 + 打开面板」，任何路径都不自动安装——装必须用户自己点

一个插件管 N 个插件（批量）

import { createMultiHostUpdate } from 'dsh-plugin-update/batch'
import { mountUpdateBatchPanel } from 'dsh-plugin-update/panel-batch'

const multi = createMultiHostUpdate({ ctx, logCtx }, {
  prefix: 'life',
  selfKey: 'life-pack',            // 「自己」排最后：自更新安全
  targets: [{ key, title, packageName, prefix }, …],
})
for (const [name, h] of Object.entries(multi.handlers)) registry.set(name, h)

mountUpdateBatchPanel(el, { prefix: 'life', call: (n, a) => host.call(n, a) })
  • 界面是「总账 + 明细 + 动作」三层：一行一家、一行只回答「这家的下一步」；点开某家复用单插件五章内核
  • 「检查更新」一次查 N 家；「全部更新」一家收尾才起下一家，一家失败默认继续
  • 会话落盘 batch.json：关面板 / 重载 / 进程重启都不怕——batchResume 接着推，已完成的不重装
  • 跨使用范围混目标回 cross-scope，不替你跨范围抢锁；drain 默认关，要宿主自动推进得显式开

卡住了看这里

  • 电话名对不上 → 两边的 prefix 是否一致，派生是否重跑
  • 轮询报错 < 250ms → 调到 250 或更大
  • 私镜装不上 → 用面板给的手工命令，源按你配的原样拼
