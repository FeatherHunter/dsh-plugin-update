# 4. 批量两段式：先全查再串行装

- 状态：proposed
- 日期：2026-10-07
- 关联：[#86 内部队列与两段式](https://github.com/FeatherHunter/dsh-plugin-update/issues/86)（父图 #81） · #70（用户已拍“做”：triage Q1，#70 已转 ready-for-human 用户亲自落地） · 研究 `docs/research/20261007-issue-86-queue-two-phase.md`（§0–§8） · ADR-0003 · 规格 #591（第 5/6 条冻结）

## 背景

现状是查一个装一个交错（`driveLocked` 每次 `maxSteps: 1`，查→落盘→装→落盘→下一家；证据见研究 §2.1）。用户终态已定：先看到 N 家全查完的总账，再一家一家装，装完一家总账跳一下。#70 已验证技术可行：`batch.json` 当 durable 工作队列、`queue.json` 只当锁、消费前必重查、TTL 只当展示。#86 终裁四答：①做两段式 ②并发取 3 ③选 A 消费前重查、不做 B ④写本 ADR。细节证据与来源索引见研究报告，本 ADR 只收决策。

## 决策

### 1. 做两段式：先全查，再串行装（生产者-消费者）

- 生产者：对选中 keys 先全查成 ready 进会话（把 `checkPhone` 循环体抽成 `checkAll`，只写知识 inventory + 置 ready，不建会话、不装）。
- 消费者：复用现有 `driveLocked` / `runBatch` 串行装（ready 复用钩子已存在，驱动器零改）：安装→`settleInstall` 到终态→落盘→下一家。
- `queued` / `check-expired` 当场重查一次继续（见 §3）；第二次仍过期才记 failed。
- `settleInstall` 轮询与面板忙守卫不动。

### 2. checkPhone 受控并发取 3

- 一手来源无 3/4/5 的区分证据，取下限保守起步；常量命名 `BATCH_CHECK_CONCURRENCY = 3` 并注释“待实测上调”。
- 手写受控池（约 20 行），不新增依赖；保留“知识落盘失败不挡回包”与逐家 try/catch（allSettled 语义）。
- 回退线：并发度降到 1 即退回现状串行查，装阶段不受影响。

### 3. 单例修法选 A：消费前重查，不做 B

- 做 A：提交时无 receipt 或遇 `check-expired`，当场重查一次再提交（补全 `defaultInstall` 已有半条路）。不碰 `host.ts` 单例纪律（规格 #591 第 6 条冻结）。
- 不做 B（`Map<key,receipt>` + 按目标常驻 reader）：省的只是 N 次轻量 registry GET，不省串行安装时间，却要改单槽语义、触冻结、回归面大。仅当实测证明 A 案不可接受才重开，且先走 #591 破冰，不与 A–C 并行。
- 已知成本：全查 N 家后串行装，除最后查到的那家外每家首次提交大概率过期（单例挤占机制见研究 §2.5），即每家约 2 次 check 联网；queue 占位可能闪一下（若扰民，实现票内改“装前先重查”，不另起决策票）。

### 4. 公平性有界（约五个插件共用同一更新队列）

- `queue.json` 仍单份共享、单队列串行（重申 ADR-0003 §4，一个字不改）。
- 无 N 席预占：批量一次只占一席；逐家占位即放——某家安装时占位，`settleInstall` 到终态即撤，占位不跨家。
- 他家 FIFO 穿插：家与家之间，他家意向按 FIFO 穿插；批量遇 `queued` 整轮停、让出队首，轮到自己再续（断点续跑：终态行不重装）。
- 已知边角：超长批量下他家意向 TTL 过期重排——意向过期只清 waiting，幂等重排即可，不判失败；属已知可接受边角，不另起决策。

### 5. 不变量重申（一个字不改）

- 检查结果不参与安装决策，一轮开始仍实时重查；幂等编号、每步落盘、一次只推一家、失败继续下一家、单队列串行、selfKey 排最后、跨 scope 拒绝、面板忙守卫。
- 面板只渲染不推导：总账与行相位只展示账本与知识，不做安装决策推导。
- TTL 只当展示/排号：正确性不依赖 TTL（两段式下预查凭证过期是算术必然，靠消费前重查兜底）。
- 四电话形状与快照六字段冻结；不新增依赖与子路径；用户可见文案零增量（`gate:bilingual` 须过）。

## 反向范围

不做 B 案（常驻 reader）；不调 TTL 数值；不动驱动之外的语义（`settleInstall`、面板忙守卫、幂等编号、落盘颗粒度均不动）；不改四电话形状与快照六字段；不新增依赖与子路径。

## 后果

- 正面：一次点选看到 N 家总账再逐家装，与用户终态一致；装阶段复用现有驱动，增量最小；与 ADR-0003 §4 同构（预查进 inventory 只展示），并钉死差分（驱动语义变更），免后人误读 0003 反向范围。
- 代价：每家约 2 次 check 联网；queue 占位可能闪一下（见 §3）。
- 观测附录（实现票顺手打点）：每家 check/install 耗时、重查计数、最大在飞数；并发 4/5 待实测数据另起调参票。
- 回退线：并发降 1 即退回串行查；两段式若有问题则停新驱动、退回交错（账本形状未变，可退）。

## 拆票清单（本票只决策不实现，实现另起票；TDD 先红后绿）

- 票 A（查并发 3）：`checkPhone` 抽 `checkAll` + 受控池（§2）；单测用假 transport 断言全查写 inventory、不建会话、逐家错误隔离、落盘失败不挡回包、最大在飞数 ≤ 3。
- 票 B（两段式驱动 + 装前重查）：`installPhone` 两段化 + `defaultInstall` 遇 `check-expired` 重查一次（§1/§3）；复用 `driveLocked` / `runBatch`，`settleInstall` 不动；单测断言“先 N 个 check 再 N 个 install”顺序、重启恢复（终态不重装）、过期重查继续（#70 验收 1–3）；覆盖 skipped + selfKey 最后 + `stopOnFailure=true` 三组合。
