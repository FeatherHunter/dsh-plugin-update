# 3. 批量更新的知识与一轮

- 状态：已采纳
- 日期：2026-10-06
- 关联：[#59 总账面板三问](https://github.com/FeatherHunter/dsh-plugin-update/issues/59)

## 背景

总账面板同时回答两个问题，但只给了一套账本：每一行的“下一步”（知识，跨批次有效）与上一轮“全部更新”的生死（一轮，有起点、有终态、有属主）都读同一份 `batch.json`。检查结果只活在各宿主进程的内存快照里，面板行相位只认账本，于是空账本点“检查更新”总览不动；轮次级动作挂在行相位判据上，于是无会话也能点“接着上次”并报假成功；生命周期事实只写在文档，面板从不陈述；账本按使用范围共享、无属主，第二家批量集成方上线即撞。

## 决策

### 1. 知识、一轮、属主各回各家

- 知识：`update-queue/<指纹>/<owner>/inventory.json`，只由查新全量重写，只做展示，永不参与安装决策。
- 一轮：`update-queue/<指纹>/<owner>/batch.json`，只由用户安装意图创建、只由驱动写。
- 属主即批量前缀（集成方唯一身份）；旧无属主 `batch.json` 不读、不删、不接管（Q2=A，不猜归属）。

### 2. 行的下一步是推导出来的

无轮次 + 行待查时按知识展示（有新版 / 已是最新 / 还没查过 / 这次没查到）；有没做完的一轮时按执行态展示，并挂“上一批没做完”轮次标记，不改写下一步。

### 3. 打开即查默认开 + 自动续与显式并存

面板偏好 `prefs.json`（用户偏好 > 集成方选项 > 缺省），60 秒节流 + 在途抑制 + 入口预查共用时间戳去重（一击只查一次）；自动查失败只标行，不弹红条。自动继续每挂载一次、仅本属主未终态、仅空闲，常开不另加开关，与显式按钮并存；无事可续如实回 `resumed:false`，杜绝空话成功。

### 4. 不变量（Archive）

检查结果不参与安装决策，一轮开始仍实时重查；幂等编号、每步落盘、一次只推一家、失败继续下一家、单队列串行（`queue.json` 仍单份共享，取消只清自己账本）——一个字不改。

## 反向范围

不做设置中心、TTL/过期策略、跨集成方共享知识库、安装回滚、不动单插件面板、不改驱动语义。
