# 2. 更新日志展示可信度：必显/诚实截断/撤回警告/破坏标记

- 状态：已采纳
- 日期：2026-10-06
- 关联：[#39 changelog 展示优化地图](https://github.com/FeatherHunter/dsh-plugin-update/issues/39)、[#40 规格终裁（含破冰）](https://github.com/FeatherHunter/dsh-plugin-update/issues/40)、[#43 规格单](https://github.com/FeatherHunter/dsh-plugin-update/issues/43)、[#41 实现+测试](https://github.com/FeatherHunter/dsh-plugin-update/issues/41)、[#42 文档+发版](https://github.com/FeatherHunter/dsh-plugin-update/issues/42)

## 背景

#38 落地了更新日志无脑接入（`updateChangelog` + 面板 `autoChangelog` 默认自动），但展示不可信：Security 默认折叠导致看不见且进不了页面查找；截断无说明导致用户误以为看到全部；目标版本 yanked 只在标题尾部小字；破坏性变更淹没在普通条目；作者无发布前校验手段。约束：不动四电话形状与快照六字段，无新依赖无新子路径，D5 主题 DOM 顺序冻结。

## 决策

### 1. Security 进 MUST_SHOW（唯一动既有逐字行为之处）

`Security` 与 `Added/Fixed/Changed` 同级展开渲染；`Deprecated/Removed` 仍折叠。理由：安全 urgency 与折叠语义冲突，且折叠内容进不了页面查找。接受一次快照 churn，DOM 顺序不动，D5 只换肤。

有限豁免：必显配额内全显（每类 200 条），超限部分收进该类内部 `<details>` 并标计数；64K 全文墙与单条 500 字墙保留。

### 2. 截断只补可见性，不动数值

100 节/200 条/500 字/64K 数值不动。解析附计数元数据（只记数字不留文本）；超限类标题下小字“共 M 条，仅显示前 N 条”（M 原始条数、N 实际渲染数，多版本各自标）；未超限不打扰。

### 3. yanked 只看 to 版，纯展示不碰门控

保留每节标题“· 已撤回”后缀；02 章内部 rangeTitle 下方加 warn 横幅（现有警告 tone，不进全局横幅），文案冻结：“目标版本 X.Y.Z 已被作者撤回（yanked），安装不受影响，继续前请确认。”中间版本不刷横幅。快照门控与区间算法不动，安装不受影响。

### 4. BREAKING 只认条目开头，正文不动

文法：条目去标后去空白后开头匹配，大小写不敏感，中英文冒号皆收，匹配前剥行首加粗/引用装饰；命中则行首徽标（`role=img`）+ 前缀加粗，正文一字不动；正文中间散文永不匹配。疑似误写只报 `W_BREAKING_MAYBE`，不阻断。

### 5. 新增纯校验函数，不进运行时

`validateChangelog(markdown)` 零导入、永不抛错，与 parse 共享同一套标题/分类/条目扫描逻辑（不允许第二套正则）。回 `{ ok, diagnostics: { line, code, hint }[] }`，line 为原文件 1-based 行号，按行号排序；未知码按 `E_`/`W_` 首字母降级展示。码表见 #40（3 Error 会丢内容，5 Warning 含撤回/截断预告/超 64K/空文件）。仅 CI/发布前调用，面板与宿主运行时永不调用。

### 6. 记住按版本，失败退避（澄清 #38 矛盾）

成功与取不到（null）按版本永久记（面板内存会话级 + 宿主进程级，不落盘；显式文本永不覆盖）。传输失败不进缓存：手动查/换版/重开立即重问，轮询按退避时间问。退避收敛为 `shouldFetchChangelog` 纯策略，三处调用方（宿主电话、单面板、批量按行）共用规则、各存各的状态。changelog-io 三墙（8MB/32MB/64K）不动，仅澄清 memo 策略注释。

## 为什么不是别的做法

| 考虑过 | 为什么否掉 |
| --- | --- |
| Security 仅红点展开 | 红点仍需一次点击且进不了页面查找，urgency 要求零点击可见 |
| 截断改数值或全显 | 全显可卡死面板；改数值动 #23 冻结的截断语义，本次只补可见性 |
| yanked 进快照门控/全局横幅 | 撤回是日志驱动，快照是状态驱动，两者混用会误拦安装；纯展示 + 文案写清“不受影响” |
| 破坏标记改正文或匹配散文 | 违背 #23“宁可丢字不改写”；散文匹配误伤率高，只认行首 |
| 校验器进运行时/阻断误写 | 运行时调用增加失败面；误写误报率高，只 warning 不阻断 |
| 记住落盘化 | 日志随版本走，内存 + 进程级已够用；落盘新增一致性负担 |

## 后果

- 正面：更新说明可信（必显可查找、截断诚实、撤回显眼、破坏一眼可见），作者发布前一次修完写法问题，失败重试语义三处一致。
- 代价：Security 一次快照 churn；校验器要求作者先修 3 类 Error（否则面板丢内容）。
- 非目标：裸 URL 可点、文件名大小写回退明确不做；四电话形状与快照六字段冻结。
