# 野外取样：插件 CHANGELOG 到底用了哪些 Markdown 构造

- 票号：wayfinder 研究票 #110
- 日期：2026-10-14
- 语料：367 个原始命中 → **97 份唯一文件**（95 份真实 CHANGELOG.md + 2 份仓内研究笔记样本）
- 分析对象：`src/changelog.ts` 的**真实代码**（`RE_*` 正则与 `parseChangelog` / `validateChangelog` 逐字未改，见 §7）

一句话结论：野外 changelog 用到的 Markdown **构造种类很窄**（列表 + 行内代码 + 链接 + 少量粗体/斜体，没有表格、任务列表、脚注、HTML 注释、删除线、`<details>`）。真正打断现解析器的不是语法复杂度，而是**标题形态的自由度**（71 种小节标题写法、版本标题跑到 H1/H3/H4/setext、三段式版本号假设）和 **64 KiB 截断**。语料上 `parseChangelog` 只从 23/95 份文件里收到 723 条条目，而全文条目行有 13548 行。

## 3. 三档判定

### 3.1 必须支持

1. **`## ` 二级版本标题**（裸/方括号/`v` 前缀/日期/可链接）——2734 处，是唯一的版本容器；现状已支持，别退化。
2. **`### ` 的 Keep a Changelog 六类精确名**（英/中）——410 处 / 24 份，是现在唯一能正确收条的路径。
3. **无序列表顶层项** `- ` / `* `——13548 行 / 92 份，正文主体。
4. **行内代码** ——4914 行 / 81 份；作者原文（建议里的 `--flag`、版本号）必须逐字保真。
5. **绝对链接与裸 URL** ——6286 + 6671 处；丢掉就等于丢掉发布说明的出处（PR/issue/compare）。
6. **`#123` issue 引用** ——3726 处 / 57 份；是「这次升级跟我有什么关系」的唯一定位线索。
7. **中英并排的小节标题**（`### Fixed / 修复` 83 处、`### Added / 新增` 74 处、`### Changed / 变更` 40 处）——同工作区插件正在用；要么收，要么在 `E_CATEGORY` hint 里明确禁掉（现状是 197 个这类标题连同其下条目一起静默丢弃）。
8. **续行/嵌套条目**（缩进行）——2729 行 / 21 份；现在靠 `src/changelog.ts:332-340` 的续行合并保原文，方向对。
9. **超长条目**（>500 字符）——39 处 / 14 份，本仓自己的 `CHANGELOG.md:116` 就是 550 字符；现状被截成 500 + `…`。
10. **`## [Unreleased]`** ——5 处；解析器收成 `Unreleased` 条目（渲染与区间忽略），行为合理，保留。

## 5. 建议（可直接开票）

1. **分类标题别名**（收益最大）：至少收 changesets 家族（`Patch/Minor/Major Changes`、`Features`、`Bug Fixes`、`Chores`、`Commits`、`Merged`、`Documentation`、`Refactors`、`PRs`）、大小写变体、以及 `A / B` 中英并排形态；否则就把它变成 `E_CATEGORY` 的 hint 文案（现状是静默丢 10618 条）。
2. **截断要说话**：`W_TRUNCATED_FILE` 带上「丢掉 N 条 / M 个版本标题」；9 份文件、2245 条、449 个版本标题值得作者知道。
3. **版本标题层级放宽或 warn**：H1/H3/H4 里出现三段版本号（316 + 66 处）与 setext 版本标题（58 处）至少应报 hint。
4. **续行合并加护栏**：只合并「纯文本折行」，遇到列表标记/围栏/表格/4 空格代码不拼（`332-340`）。
5. **原文保真**：`137` 的 `\s+` 会吃掉双语并排的双空格（本仓与 dsh-im 都有），可考虑只压水平空白并保留连续两个空格。
6. **解析前剥 BOM**（`269`）。

## 6. 方法与复现

- 只用 `glob` / `read` / `grep` + 少量 Node 一次性脚本（在 `%TEMP%\changelog-corpus-110\`，仓库外）：`manifest.json`（367 条命中清单）、`analyze3.cjs` / `report3.json`（逐文件指标）、`final3.cjs` / `final.json`（构造计数与孤儿归因）、`cmp.cjs`（校验器 vs 解析器口径交叉验证）、若干探针脚本。
- 探针与语料统计调用的是**真实的** `src/changelog.ts`：把它复制成 `changelog-under-test.ts`，仅去掉 3 行 `import` 并补 4 个桩函数，`parseChangelog` / `validateChangelog` / 所有 `RE_*` 逐字未改。
- 去重按 SHA-256，分组优先级 repo-own > 同工作区插件 > asar 提取 > node_modules > 研究笔记。
- 行/文件两个口径全程分开标注；围栏与注释用与解析器同款状态机（`296-300`）屏蔽，避免把围栏里的 `/^\s*[-*+]\s+/` 数成条目。
- **现场修正记录**：早期一个 `### Added:` 探针因为探针脚手架的 `.replace()` 只作用在末尾行而实际没替换，得出了「冒号可收」的错误结论；已作废并用修正后的探针重测（`### Added:` 实为 **丢**）。本报告不含那个错误结论。

## 7. 未决问题

- changesets 的 `.changeset/*.md`、GitHub Releases HTML、其他语言生态（Go/Rust/Python 的 CHANGELOG）未取样；本语料里 changesets 只以 `### Patch Changes` 形态出现。
- 「保真模式」是否需要：现在 `truncateBullet` 会改写作者原文（空白压缩 + 截断），与本仓 `331` 行「宁可丢字，不改写作者原文」的注释目标并不完全一致。
- 中文别名要收到什么程度（子串匹配被 `109-110` 明确拒绝；那 `修复：xxx` 这类前缀+冒号形态是否值得单列规则）。
- 64 KiB 上限是否提高：三份超过 130K 字符的 changelog（`openai`、`@anthropic-ai/sdk`、`axios`）在截断下丢的比收的多。
